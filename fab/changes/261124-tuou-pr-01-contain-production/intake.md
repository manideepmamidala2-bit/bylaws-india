## Origin

> Implement PR 01 (Contain Production) per docs/plans/pr-series/00-overview.md and docs/plans/pr-series/01-contain-production.md: mark release 1.0.0 of in-ka-bengaluru-south as withdrawn in public/data/manifest.json and remove its files from public/data/, filter visibility:test jurisdictions at build time on the server via SHOW_TEST_JURISDICTIONS, update public copy across Home/Map/Sources/Documents/Timeline/Data/About (removing synthetic claims, rule/plan refs, repo paths, backticks, em dashes), and add test blocking local source_url in non-test manifests.

Initiated following Audit 3 (`docs/reports/2026-11-24-audit-plan-v2.pdf`) and the PR 01–11 remediation plan series (`docs/plans/pr-series/00-overview.md` and `docs/plans/pr-series/01-contain-production.md`). In our pre-flight discussion, the user confirmed:
1. Using the Fab workflow with 1 Fab change per PR (11 sequential changes), stopping at every PR for owner review and merge (Rule R18).
2. Syncing `main` to `859fa77` and copying the 12 plan files into `docs/plans/pr-series/`.
3. Mapping `web/public/data/` in the plan prose to the repository's root `public/data/` directory where the Next.js application lives.

## Why

1. **Problem**: Audit 3 identified that all Bengaluru South data in release `1.0.0` (28 PDFs, wards, zones, corporation boundary, clauses, amendments) was synthetically generated by `scripts/build_bengaluru_south_sources.py` and published in `public/data/in-ka-bengaluru-south/1.0.0/` as if it were in-force law. Additionally, `app/page.tsx` is a client component that checked `process.env.VERCEL_ENV` in the browser (where non-`NEXT_PUBLIC_*` env vars are undefined), causing `visibility: "test"` jurisdictions (`xx-test-fixture`) to appear in production. Finally, public UI strings contain unverified claims ("verified at its official origin"), internal shorthand ("Rule R13", "Rule R14", `(R13)`), raw backticks, and em dashes (`—`).
2. **Consequence of inaction**: The live production site continues presenting synthetic demonstration data as the building law of Bengaluru South City Corporation and leaks test fixtures to production visitors.
3. **Why this approach**: PR 01 is intentionally scoped as an immediate containment PR that withdraws release `1.0.0`, deletes `public/data/in-ka-bengaluru-south/1.0.0/*`, moves test-jurisdiction filtering to server-side build time via `SHOW_TEST_JURISDICTIONS`, cleans all public copy, and adds a recurrence guard test blocking local `source_url` entries in non-test published manifests. Moving the generator script and building the full provenance gate follow in PR 02.

## What Changes

### 1. Withdraw Synthetic Release `1.0.0` and Remove Published Files (`schemas/manifest.schema.json`, `public/data/manifest.json`, `public/data/in-ka-bengaluru-south/1.0.0/`, `pipeline/bylaws/publish.py`)

- Update `schemas/manifest.schema.json`:
  - Allow `jurisdictionManifest.latest_release` to be `["string", "null"]` (null when a jurisdiction has no active published release, or `"1.0.0"` when only a withdrawn release exists).
  - Add optional `status` (`enum: ["published", "withdrawn"]`, default `"published"`) and optional `withdrawn_reason` (`type: ["string", "null"]`) on `releaseEntry`.
  - Allow `download_zip`, `sha256sums`, `declarations`, `files`, and `drafts` on `releaseEntry` to be nullable/optional when `status` is `"withdrawn"`, so a withdrawn release entry contains no downloadable file links.
  - Run `make generate` (`scripts/generate_models.py`) to sync `pipeline/bylaws/models/_generated.py` and `lib/types/generated.ts`.
- Update `public/data/manifest.json`:
  - Keep `in-ka-bengaluru-south` listed (`name: "Bengaluru South City Corporation"`, `visibility: "public"`, `latest_release: null`).
  - Mark release `1.0.0` of `in-ka-bengaluru-south` with `"status": "withdrawn"`, `"withdrawn_reason": "Synthetic demonstration data, not the law of Bengaluru South"`, and remove all file paths (`download_zip: null`, `sha256sums: null`, `declarations: null`, `files: null`, `drafts: null`).
- Delete all 41 files under `public/data/in-ka-bengaluru-south/1.0.0/`.
- Keep `scripts/build_bengaluru_south_sources.py` intact until PR 02 moves it to fixtures, and update `pipeline/tests/test_bengaluru_south_dataset.py` so tests reflect that `public/data/in-ka-bengaluru-south/1.0.0/` has been withdrawn and removed from `public/data/`.

### 2. Server-Side Build-Time Filtering via `SHOW_TEST_JURISDICTIONS` (`lib/data.ts`, `app/page.tsx`, `app/data/page.tsx`, `app/about/page.tsx`, `app/j/[id]/**`)

- In `lib/data.ts`:
  - Replace the browser-broken `VERCEL_ENV` check with a server-only environment variable check `shouldShowTestJurisdictions()`: returns `true` only when `process.env.SHOW_TEST_JURISDICTIONS === "true"` or `process.env.SHOW_TEST_JURISDICTIONS === "1"`.
  - Filter `manifest.jurisdictions` on the server in `getVisibleJurisdictions(manifest)` (and provide a server helper `fetchFilteredManifest()` that strips `visibility: "test"` jurisdictions when `shouldShowTestJurisdictions()` is `false`) so the manifest and page props handed to any page or client component are already filtered at build time on the server.
  - Update `findJurisdictionRelease` and `fetchJurisdictionDataset` so that:
    - If a jurisdiction has `visibility === "test"` and `!shouldShowTestJurisdictions()`, its dataset is not returned in production builds.
    - If a jurisdiction has only withdrawn releases (or `latest_release === null`), `findJurisdictionRelease` returns `{ jurisdiction, release: null }` and `fetchJurisdictionDataset` returns a bundle with `release: null` and empty documents/clauses/zones so the jurisdiction routes render the honest `"No data published yet"` state instead of crashing or 404ing.
- Convert `app/page.tsx` from a `"use client"` component to a Server Component (or server wrapper passing pre-filtered manifest props) so filtering executes strictly at build time on the server and never depends on browser `process.env`.
- Add automated tests in `__tests__/` verifying that when `SHOW_TEST_JURISDICTIONS` is unset/false, the manifest and page props produced on the server contain zero `visibility: "test"` jurisdictions.

### 3. Honest Copy and Editorial Hygiene Across All Pages and Components (`app/**`, `components/**`)

- **Home page (`app/page.tsx`)**:
  - Replace dataset counts and the phrase `"verified at its official origin"` with a concise, honest status block: what Structured Building Bylaws is, that the first Bengaluru South release (`1.0.0`) was synthetic demonstration data and has been withdrawn, and that real regulatory documents and maps are being acquired and will be published as they are verified.
  - List `Bengaluru South City Corporation` with the status badge/label `"No data published yet"`.
- **Jurisdiction pages (`app/j/[id]/page.tsx`, `app/j/[id]/sources/page.tsx`, `app/j/[id]/clauses/page.tsx`, `app/j/[id]/documents/[doc]/page.tsx`, `app/j/[id]/timeline/page.tsx`, `app/j/[id]/review/page.tsx`)**:
  - When a jurisdiction has no published release (`release === null`, as for `in-ka-bengaluru-south`), render a clean `"No data published yet"` state with no generated clauses, zones, boundaries, or source checksums.
- **Data page (`app/data/page.tsx`)**:
  - List release `1.0.0` of `in-ka-bengaluru-south` as `"Withdrawn: synthetic demonstration data, not the law of Bengaluru South"` (matching `00-overview.md` §7 and `01-contain-production.md` §1/§3), with no download bundle or file links.
  - For jurisdictions with no active release, show `"No data published yet"`.
- **About page (`app/about/page.tsx`)**:
  - Remove any claims about verification at official origin; describe the methodology and verification states (`unverified`, `machine_checked`, `human_verified`) in plain English and state the current project status honestly (release `1.0.0` withdrawn; real acquisition in progress).
- **Public copy sweep across all `app/**` and `components/**` files**:
  - Remove all internal rule references (`Rule R13`, `Rule R14`, `(R13)`, `(R14)`, `Rules R2, R9, R10`, `Rule R6 & R9`, etc.).
  - Remove any plan references (`Plan v2.0`, etc.).
  - Remove repository paths and raw backticks (e.g. `` `.zip` ``, `` `SHA256SUMS` ``, `` `CSV` ``, `` `JSON` ``, `` `declarations.json` ``, `` `@v1` ``, `` `@v2` ``) from rendered copy.
  - Remove all em dashes (`—` / `\u2014`) from interface strings across `app/` and `components/`.
  - Shorten labels that wrap at 1280 px.

### 4. Minimal Recurrence Guard Test (`pipeline/tests/` and `__tests__/`)

- Add a test in `pipeline/tests/` and `__tests__/` that inspects `public/data/manifest.json` and fails if:
  1. Any published (non-`visibility: "test"`, non-`status: "withdrawn"`) manifest release entry references any local `source_url` (e.g., `file://`, relative path, `data/sources/`, or anything not starting with `http://` or `https://`) in its published `documents.json` or `sources.json`.
  2. Any withdrawn release entry in `public/data/manifest.json` exposes downloadable file URLs (`download_zip`, `files`, etc.).
- Update `docs/progress.md` to record PR 01 status.
