# System Architecture & Core Invariants

**Domain**: architecture

## Overview
`bylaws-india` (**Bylaw One** — `"Bengaluru's building rules. One code."`) is an open-code (Apache-2.0) and open-data (CC BY 4.0) machine-readable dataset, consolidated building code, and plain-language web viewer for Indian building and municipal bylaws (a5ou, 8ay2, izxl, tuou, peq2, 4e7t, ucy1, bups, jqph, mspg, 3t3i, h24h). The repository is split into an offline Python 3.12+ data pipeline (`pipeline/`) and a read-only Next.js web application at the repository root (`app/`, `components/`, `lib/`, `public/`, with `.vercelignore` excluding `pipeline/` so Vercel deploys a single `bylaws-india` project), connected strictly through fifteen versioned JSON and GeoJSON data contracts at Unified Schema `1.4` defined in [data-contracts](/schemas/data-contracts.md) (a5ou, 8ay2, izxl, 4e7t, ucy1, h24h). Release `4.0.0` publishes the parent Greater Bengaluru jurisdiction (`in-ka-bengaluru`) and five child City Corporations (`in-ka-bengaluru-central`, `-north`, `-south`, `-east`, `-west`) with single-source shared document, parameter, and provision deduplication, thin City Corporation diff layers verified by a 5-corporation CI parity check (`pipeline/tests/test_pr12_greater_bengaluru.py`), per-chapter `<doc_id>.outline.json` + `<doc_id>/chapters/<chapter_eid>.json` payloads, machine-enforced verbatim provision and home-page FAR story excerpt text fidelity (`pipeline/bylaws/fidelity.py`, `pipeline/tests/test_text_fidelity.py`) backed by a committed SHA-256-verified page-text store (`data/page_text/`), separated `notes_by_site` and `summary_by_site`, explicit `instrument_type` classification, `plain_title` register display names, full consolidated code, 313 deduplicated and supersession-resolved building parameter records (`parameters.json`) with per-parameter plausibility bounds, hectare-to-`m²` interval normalization, non-FAR row exclusion, CI parameter overlap and band continuity checks (`check_parameter_overlaps`, `check_band_continuity`), and sentence parking prose, a 6-step deterministic statutory plot resolver (`jurisdictions/resolution.yaml`, `pipeline/bylaws/resolver.py`, `lib/resolver.ts`), an 8-layer MapLibre GL JS + `@protomaps/basemaps` (`light`) interactive map with build-time `place-index.json` + `MiniSearch` place search, a 6-group **Place Card** showing governing zone rules, multi-sheet MapLibre `image` overlays with opacity control, and `/j/[id]/wards` (**Browse by ward**), static machine/AI endpoints (`/llms.txt`, `/llms-full.txt`, `.md` page mirrors, `/api/v1/` with OpenAPI 3.1, `schema.org/Legislation` JSON-LD, Frictionless `datapackage.json`, `/updates.xml` Atom feed, and `/use-with-ai`), a serverless two-verifier workshop verification workflow (`bylaws tasks create`, `/verify/<task-set>`, `bylaws verify import`), pilot/trust/partner surfaces (`/pilot`, `/checks`, `/join`, `/press`, `docs/partners/`), and CI `gitleaks`, WCAG 2.2 AA (`axe-core`), and Lighthouse mobile (`performance >= 70`, `accessibility >= 95`) gates (4e7t, ucy1, bups, jqph, mspg, 3t3i, h24h).

## Requirements

### Requirement: Two-Half Architecture, Repository Root Discovery, Out-of-Git Range Storage, and Open-Data Governance
The repository MUST maintain a strict boundary between the local Python processing pipeline (`pipeline/`, pinned to Python `3.12` via `.python-version` and `pipeline/.python-version`) and the read-only Next.js web viewer at the repository root (`app/`, `components/`, `lib/`, `public/`), sharing declarative jurisdiction configurations in `jurisdictions/` and JSON Schemas in `schemas/` (a5ou, 8ay2, 4e7t). Repository root discovery (`resolve_repo_root()` in `pipeline/bylaws/root.py`) MUST resolve the repository root deterministically in priority order: `--root <path>` CLI option on `bylaws`, `BYLAWS_ROOT` environment variable, or an upward directory walk from `Path.cwd()` for the `bylaws.toml` root marker file, raising `click.ClickException` if none is found (8ay2). All contact and organisation metadata (`contact.email` and `organisation.name`) MUST be centralized in `bylaws.toml` (`[contact]` and `[organisation]` sections, left as owner placeholders) and read through `pipeline/bylaws/config.py` and `lib/site-config.ts` without scattering hardcoded email addresses or organisation names across pages or templates (h24h). Working directories `data/raw/`, `data/interim/`, and `data/processed/`, as well as generated Bengaluru release payloads (`public/data/in-ka-bengaluru*`, `~248 MB`) and `basemap.pmtiles` (`33 MB`), MUST be excluded from git tracking via `.gitignore` and served from HTTP range-request (`206 Partial Content`) and CORS-enabled (`Access-Control-Allow-Origin`, `Access-Control-Expose-Headers: Content-Range, Content-Length, Accept-Ranges`) storage (`pipeline/bylaws/storage.py`, `scripts/sync_storage.py`, verified by `pipeline/tests/test_range_storage.py`), whereas `public/data/xx-test-fixture/`, `public/data/manifest.json`, committed page-text stores in `data/page_text/`, pre-built workshop task sets in `public/data/tasks/`, manual curation and verification files in `data/overrides/<jurisdiction>/`, verification reports in `data/reports/<jurisdiction>/`, owner precision review sheets in `docs/review/relations-labelling.md`, human-readable source registers in `docs/sources/<jurisdiction>.md`, architecture decisions in `docs/decisions/`, partner documents in `docs/partners/` (`offer.md`, `workshop-kit.md`, `internship.md`, `mou-template.md`, `charter.md`, `demo-script.md`), and open-repository governance and citation files (`README.md`, `LICENSE` under Apache-2.0, `LICENSE-DATA.md` under CC BY 4.0 with attribution to Bylaw One, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` under Contributor Covenant 2.1, `SECURITY.md`, `GOVERNANCE.md`, `CITATION.cff`, `.zenodo.json`, `.github/ISSUE_TEMPLATE/config.yml`, `report-problem-with-a-rule.yml`, `suggest-a-source.yml`, `join-the-pilot.yml`, `docs/dependencies.md`, `docs/data-sources.md`, and `docs/progress.md`) MUST be tracked in git and scanned for secrets across full git history and on every push/PR via `gitleaks` in `.github/workflows/ci.yml` (a5ou, 8ay2, izxl, fcwm, 4e7t, ucy1, bups, 3t3i, h24h).

### Requirement: Mandatory CLI Jurisdiction Parameter and Pipeline Subcommands (Rule R1)

Every jurisdiction-scoped subcommand MUST require `--jurisdiction <id>` with no default value (a5ou, fcwm, h24h). Neither `pipeline/` nor the root Next.js source files (`app/`, `components/`, `lib/`) SHALL contain hard-coded jurisdiction IDs, fixture literals (`_fixture-test`, `xx-test-fixture`), `country == "XX"` branches, city names, planning district numbers, zone code lists, or bounding coordinates, nor the strings `"prototype"` (case-insensitive) or `"(example)"` in web source or jurisdiction display names (a5ou, 8ay2, izxl):

### Requirement: Core Engineering Rules (Rules R1–R16)
All pipeline stages and web components MUST uphold the sixteen non-negotiable engineering and legal invariants (a5ou, 8ay2, izxl, fcwm, 4e7t, h24h):
- **R1 (Zero Jurisdiction Hard-Coding)**: Jurisdiction-specific metadata resides exclusively in `jurisdictions/<id>.yaml`, `jurisdictions/resolution.yaml`, and `data/overrides/<jurisdiction>/` (a5ou, 8ay2, izxl, 4e7t).
- **R2 (Mandatory Provenance)**: Every clause carries `doc_id`, `citations` (with 1-based `page`, normalized `[x0, y0, x1, y1]` `bbox`, and `text_excerpt`), and `verification`; every parameter record carries cell-level `source` (`doc_id`, `eid`, `table_eid`, `row_index`, `col_index`, `column_header`, `row_header`, `cell_text`, `page`, `bbox`, `official_url`, `archive_url`); every zone feature carries `source_map`, `georef_run`, `extraction_method`, `source_attribution`, and `verification`; every clause–zone tag carries a quoted `reason` (a5ou, 8ay2, izxl, 4e7t).
- **R3 (Explicit Legal Status)**: Documents, clause trees, clauses, and parameter records carry an explicit `legal_status` (`in_force | draft | superseded | withdrawn | status_unknown`), and `draft` artifacts are published separately from `in_force` regulations, excluded by Step 1 of `resolution.yaml`, and badged in the UI (a5ou, 8ay2, izxl, 4e7t).
- **R4 (Strict Permissive-Only Licensing)**: All Python distributions and direct + transitive npm packages in `package-lock.json` / `node_modules` are restricted to the explicit permissive allowlist (`MIT`, `Apache-2.0`, `BSD-2-Clause`, `BSD-3-Clause`, `BSD`, `ISC`, `PSF-2.0`, `0BSD`, `CC0-1.0`, `Unlicense`, `OFL-1.1`, `MPL-2.0`, plus documented `LGPL` runtime library imports in `docs/dependencies.md`); `GPL`, `GPLv3`, `AGPL` (`PyMuPDF`, `Unstract`, `MinerU`, `Marker`), `UNKNOWN`, and empty licences are rejected by `pipeline/tests/test_r4_licences.py` in CI (a5ou, 8ay2, izxl, h24h).
- **R5 (Immutable Raw Sources)**: Downloaded files in `data/raw/` are never modified in place and are verified via SHA-256 checksums in `<doc_id>.meta.json` (a5ou, 8ay2).
- **R6 (Deterministic Reproducibility)**: Generated files in `data/processed/` are never hand-edited; all manual corrections, zone tags, map curations, and human verifications are committed under `data/overrides/<jurisdiction>/*.yaml`, and all generated timestamps (`retrieved_at`, `generated`, `released_at`, ZIP member timestamps) derive deterministically from `SOURCE_DATE_EPOCH` so repeated runs produce byte-identical outputs and `.zip` archives (a5ou, izxl, h24h).
- **R7 (Fail Loudly)**: Unreadable manifests, unknown `map_id` curations, missing CRS metadata, and validation failures raise `click.ClickException` or `ValueError` and exit non-zero (8ay2, izxl).
- **R8 (No Defaults That Strengthen a Claim)**: Neither the pipeline nor the web UI supplies fallback defaults for missing regulatory status or source pages; missing or contested status renders `STATUS UNKNOWN` in `StatusBadge`, and a clause without a citation page renders `"No source page recorded"` without an anchor link (8ay2, izxl).
- **R9 (Immutable Verified Records)**: Verified records (`human_verified` or `machine_checked` when versioned) are never mutated in place by `apply-overrides`; when an override changes a verified clause or zone, the existing `<id>@v<N>` record is retained with `record_superseded_by` (and `superseded_by`) set to `<id>@v<N+1>` and a new `<id>@v<N+1>` record is appended with `record_version = N + 1`, `record_supersedes = "<id>@v<N>"`, and `record_change_reason` (8ay2, izxl).
- **R10 (Honest Verification)**: Automated pipelines mark verified records `machine_checked` (or `unverified` before check) and never mark records `human_verified`; a record becomes `human_verified` (`"Verified by a person"`) only after at least two independent human `match` verdicts and zero `mismatch` verdicts imported via `bylaws verify import` into `data/overrides/<jurisdiction>/verifications.yaml` (izxl, 4e7t, h24h).
- **R11 (Falsifiable Tests and Hand-Written Golden Fixtures)**: Every pipeline invariant, parameter parser rule, and plot resolver target is verified by falsifiable unit tests in `pipeline/tests/` and `__tests__/`, plus hand-authored golden expectations in `pipeline/tests/golden/xx-test-fixture/` (izxl, 4e7t).
- **R12 (Separation of Legal Status and Record Version)**: `legal_status` and `record_version` (`record_supersedes`, `record_superseded_by`, `record_change_reason`) are distinct fields; only current record versions (`record_superseded_by == null`) appear in default UI lists, with `"v2 · corrected from v1"` expanding to version history and never badged as `SUPERSEDED` legal status (izxl).
- **R13 (Text Rights)**: Only documents with `text_rights.mode == "full_text"` have full text published; copyrighted standards (`nbc-2016`) and non-redistributable maps (`aai-cczm`) carry `text_rights.mode == "reference_only"` and publish only citation metadata, cited provisions, and where to obtain them without reproducing their text or height surfaces (izxl).
- **R14 (Explicit Attribution of Derived Work)**: Consolidated `"as amended"` documents (`consolidated.json` and per-chapter snapshots), extracted parameter records (`parameters.json`), statutory resolution rules (`resolution.yaml`), georeferenced zones (`zones.geojson`), and buffer overlays (`overlays.geojson`) carry `derived: true` and a `method` / notice description, are labelled as derived work in the UI, and link back to the underlying official sources (izxl, 4e7t).
- **R15 & R16 (Retrieval Provenance and Synthetic PDF Denylist)**: Every acquired non-test source carries an HTTP `retrieval` record with Wayback Machine archive snapshot metadata, and non-test PDFs matching the `bylaws.toml` creator/producer denylist are rejected by `bylaws check-provenance` (fcwm).

## Design Decisions

### Permissive PDF and Geospatial Stack (R4 Licensing Hygiene)
