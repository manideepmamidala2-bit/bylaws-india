# System Architecture & Core Invariants

**Domain**: architecture

## Overview
`bylaws-india` is an open-code (Apache-2.0) and open-data (CC BY 4.0) machine-readable dataset and web viewer for Indian building and municipal bylaws, governed by the PR 01–11 remediation series in `docs/plans/pr-series/` (`00-overview.md`) (a5ou, 8ay2, izxl, tuou). The repository is split into an offline Python 3.12+ data pipeline (`pipeline/`) and a read-only Next.js web application at the repository root (`app/`, `components/`, `lib/`, `public/`, with `.vercelignore` excluding `pipeline/` so Vercel deploys a single `bylaws-india` project), connected strictly through versioned JSON and GeoJSON data contracts defined in [data-contracts](/schemas/data-contracts.md) (a5ou, 8ay2, izxl). In `public/data/manifest.json`, the synthetic release `1.0.0` of Bengaluru South City Corporation (`in-ka-bengaluru-south`, `visibility: "public"`) is marked `status: "withdrawn"` (`withdrawn_reason: "Synthetic demonstration data, not the law of Bengaluru South"`) with its downloadable files removed from `public/data/` and `latest_release: null` (`"No data published yet"`), while the synthetic offline fixture (`xx-test-fixture` release `0.1.0`, `visibility: "test"`) is filtered out on the server unless `SHOW_TEST_JURISDICTIONS` is enabled (a5ou, 8ay2, izxl, tuou).

## Requirements

### Requirement: Two-Half Architecture, Repository Root Discovery, and Open-Data Governance
The repository MUST maintain a strict boundary between the local Python processing pipeline (`pipeline/`, pinned to Python `3.12` via `.python-version` and `pipeline/.python-version`) and the read-only Next.js web viewer at the repository root (`app/`, `components/`, `lib/`, `public/`), sharing declarative jurisdiction configurations in `jurisdictions/` and JSON Schemas in `schemas/` (a5ou, 8ay2). Repository root discovery (`resolve_repo_root()` in `pipeline/bylaws/root.py`) MUST resolve the repository root deterministically in priority order: `--root <path>` CLI option on `bylaws`, `BYLAWS_ROOT` environment variable, or an upward directory walk from `Path.cwd()` for the `bylaws.toml` root marker file, raising `click.ClickException` if none is found (8ay2). Working directories `data/raw/`, `data/interim/`, and `data/processed/` MUST be gitignored, whereas manual curation files in `data/overrides/<jurisdiction>/`, verification reports in `data/reports/<jurisdiction>/`, human-readable source registers in `docs/sources/<jurisdiction>.md`, architecture decisions in `docs/decisions/`, and open-data governance files (`LICENSE` under Apache-2.0, `LICENSE-DATA.md` under CC BY 4.0 with attribution to `"Structured Building Bylaws"`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `CITATION.cff`, `docs/dependencies.md`, `docs/data-sources.md`, `docs/plan-v2.md`, and `docs/progress.md`) MUST be tracked in version control (a5ou, 8ay2, izxl).

### Requirement: Mandatory CLI Jurisdiction Parameter and Pipeline Subcommands (Rule R1)
The `bylaws` CLI (`pipeline/bylaws/cli.py`) MUST expose subcommands for all pipeline stages (`acquire`, `parse`, `compare`, `structure`, `amendments`, `apply-overrides`, `validate`, `geo`, `publish`, `verify-sources`), the repository-wide provenance gate `check-provenance`, and the end-to-end orchestrator `run-all` (`acquire → parse → structure → amendments → geo → apply-overrides → validate → publish`, halting immediately and reporting the stage name on failure) (a5ou, 8ay2, izxl, fcwm). Every jurisdiction-scoped subcommand MUST require `--jurisdiction <id>` with no default value (a5ou, fcwm). Neither `pipeline/` nor the root Next.js source files (`app/`, `components/`, `lib/`) SHALL contain hard-coded jurisdiction IDs, fixture literals (`_fixture-test`, `xx-test-fixture`), `country == "XX"` branches, city names, planning district numbers, zone code lists, or bounding coordinates, nor the strings `"prototype"` (case-insensitive) or `"(example)"` in web source or jurisdiction display names (a5ou, 8ay2, izxl):
- **`acquire` (`pipeline/bylaws/acquire.py`)**: Downloads remote `http(s)` PDFs, KMLs, and GeoJSONs into `data/raw/<jurisdiction>/` (skipping entries with `acquisition_status: "pending"` or `"not_found"`), follows redirects with polite retries, requests a Wayback Machine Save Page Now snapshot, writes the complete R15 `retrieval` block into `<doc_id>.meta.json`, and rejects local `source_url`s or denylisted PDF creators/producers in non-test jurisdictions (a5ou, 8ay2, izxl, fcwm).
- **`check-provenance` & `verify-sources` (`pipeline/bylaws/provenance.py`)**: `check-provenance` enforces Rules R15 and R16 across all non-test jurisdictions and PDFs (failing on local/non-`http(s)` `source_url`s, missing `retrieval` records on acquired sources, or PDFs whose `Creator`/`Producer` matches the denylist in `bylaws.toml`); `verify-sources --jurisdiction <id>` refetches each acquired source and verifies its SHA-256 against the recorded digest (scheduled weekly in `.github/workflows/verify-sources.yml`) (fcwm).
- **`parse` & `compare` (`pipeline/bylaws/parsers/`, `pipeline/bylaws/compare.py`)**: Executes real permissive adapters (`pypdfium2`, `docling` via `docling.document_converter.DocumentConverter` with no `pypdfium2` alias, and `tesseract` OCR setting `bbox: null` when word coordinates are absent), reads installed package versions strictly via `importlib.metadata.version(...)` (failing with `ClickException` if a package or binary is missing, Rule R7), and writes `data/reports/<jurisdiction>/recon.md` and `data/reports/<jurisdiction>/parser-comparison.md` (8ay2, izxl, fcwm).
- **`structure` (`pipeline/bylaws/structure.py`)**: Performs general column-aware line grouping, strips running headers and footers across pages, recognizes parts, Roman-numeral chapters (`CHAPTER I`), numbered clauses (`1.0`, `1.1`), and parent-scoped sub-items (`2.1(a)`), extracts structured tables into `tables[]` while removing flattened table rows from prose `text`, preserves Kannada text verbatim with `language: "kn"`, and avoids false clause splits on mid-sentence measurements (`3.5 m`) or years (`2020`) (8ay2, izxl).
- **`amendments` & `consolidate` (`pipeline/bylaws/amendments.py`, `pipeline/bylaws/consolidate.py`)**: Links amending instruments across amendment chains (`substitute`, `insert_after`, `insert_before`, `omit`, `modify`, `renumber`) into `amendments.json` and generates `consolidated.json` (`derived: true`, `method`, `amendments_applied[]`, `as_of_date`) wherever all applicable links have `confidence: "high"`, recording unconsolidated clauses with reasons otherwise (8ay2, izxl).
- **`geo` (`pipeline/bylaws/geo/`)**: Inspects CRS on all geospatial inputs, reprojects sources with a declared projected CRS (such as `EPSG:32643` UTM Zone 43N) to `EPSG:4326` (WGS 84), computes `area_sq_m` in metric UTM (`EPSG:32643`), rejects CRS-less inputs with `ClickException` or `ValueError`, and publishes official boundaries (`boundary.geojson`, `gba-zones.geojson`, `wards.geojson`), intersecting planning districts (`planning-districts.geojson`), master plan zones (`zones.geojson` via `vector_pdf`, `grid_georeferenced_raster`, `osm_gcp_raster`, or `imported`), derived overlays (`overlays.geojson` such as the 11 m Namma Metro underground influence zone), `geo-layers.json`, and `data/reports/<jurisdiction>/map-verification.md` (8ay2, izxl).
- **`apply-overrides` (`pipeline/bylaws/overrides.py`)**: Applies `clause_fixes`, `zone_fixes`, `zone_tags` (`clause-zone-tags.json`), and `map_curations` idempotently while preserving YAML order, skipping no-op fixes so repeated executions produce byte-identical files without inflating `@v<N>` chains, raising `ClickException` on unknown `map_id` curations, and maintaining R12 record version fields without mutating `legal_status` (8ay2, izxl).
- **`validate` (`pipeline/bylaws/validate.py`)**: Validates all processed files against Schema v1.2 contracts and writes `data/reports/<jurisdiction>/qa.md` verifying 100% status/date/page citation coverage, ≥95% `bbox` coverage, ≥98% text coverage, and zero `human_verified` agent markings (8ay2, izxl).
- **`publish` (`pipeline/bylaws/publish.py`)**: Requires `release_version` on the jurisdiction config (failing with `ClickException` if absent), fails loudly (`ClickException`) if an existing `public/data/manifest.json` is unreadable or malformed JSON, preserves all other jurisdictions and prior releases in `releases[]`, reads `licence` from `config.licence`, and publishes the release bundle, `.zip` archive, `SHA256SUMS`, `sources.json`, and `sources.csv` (8ay2, izxl, fcwm).

### Requirement: Core Engineering Rules (Rules R1–R14)
All pipeline stages and web components MUST uphold the fourteen non-negotiable engineering and legal invariants (a5ou, 8ay2, izxl):
- **R1 (Zero Jurisdiction Hard-Coding)**: Jurisdiction-specific metadata resides exclusively in `jurisdictions/<id>.yaml` and `data/overrides/<jurisdiction>/` (a5ou, 8ay2, izxl).
- **R2 (Mandatory Provenance)**: Every clause carries `doc_id`, `citations` (with 1-based `page`, normalized `[x0, y0, x1, y1]` `bbox`, and `text_excerpt`), and `verification`; every zone feature carries `source_map`, `georef_run`, `extraction_method`, `source_attribution`, and `verification`; every clause–zone tag carries a quoted `reason` (a5ou, 8ay2, izxl).
- **R3 (Explicit Legal Status)**: Documents, clause trees, and clauses carry an explicit `legal_status` (`in_force | draft | superseded | withdrawn | status_unknown`), and `draft` artifacts are published separately from `in_force` regulations and badged in the UI (a5ou, 8ay2, izxl).
- **R4 (Strict Permissive-Only Licensing)**: All Python distributions and direct + transitive npm packages in `package-lock.json` / `node_modules` are restricted to the explicit permissive allowlist (`MIT`, `Apache-2.0`, `BSD-2-Clause`, `BSD-3-Clause`, `BSD`, `ISC`, `PSF-2.0`, `0BSD`, `CC0-1.0`, `Unlicense`, `OFL-1.1`, `MPL-2.0`, plus documented `LGPL` runtime library imports in `docs/dependencies.md`); `GPL`, `GPLv3`, `AGPL` (`PyMuPDF`, `Unstract`, `MinerU`, `Marker`), `UNKNOWN`, and empty licences are rejected by `pipeline/tests/test_r4_licences.py` in CI (a5ou, 8ay2, izxl).
- **R5 (Immutable Raw Sources)**: Downloaded files in `data/raw/` are never modified in place and are verified via SHA-256 checksums in `<doc_id>.meta.json` (a5ou, 8ay2).
- **R6 (Deterministic Reproducibility)**: Generated files in `data/processed/` are never hand-edited; all manual corrections, zone tags, and map curations are committed under `data/overrides/<jurisdiction>/*.yaml`, and all generated timestamps (`retrieved_at`, `generated`, `released_at`, ZIP member timestamps) derive deterministically from `SOURCE_DATE_EPOCH` so repeated runs produce byte-identical outputs and `.zip` archives (a5ou, izxl).
- **R7 (Fail Loudly)**: Unreadable manifests, unknown `map_id` curations, missing CRS metadata, and validation failures raise `click.ClickException` or `ValueError` and exit non-zero (8ay2, izxl).
- **R8 (No Defaults That Strengthen a Claim)**: Neither the pipeline nor the web UI supplies fallback defaults for missing regulatory status or source pages; missing or contested status renders `STATUS UNKNOWN` in `StatusBadge`, and a clause without a citation page renders `"No source page recorded"` without an anchor link (8ay2, izxl).
- **R9 (Immutable Verified Records)**: Verified records (`human_verified` or `machine_checked` when versioned) are never mutated in place by `apply-overrides`; when an override changes a verified clause or zone, the existing `<id>@v<N>` record is retained with `record_superseded_by` (and `superseded_by`) set to `<id>@v<N+1>` and a new `<id>@v<N+1>` record is appended with `record_version = N + 1`, `record_supersedes = "<id>@v<N>"`, and `record_change_reason` (8ay2, izxl).
- **R10 (Honest Verification)**: Agent-verified records are marked `machine_checked` (or `unverified` before check); zero records are marked `human_verified` by automated pipelines (izxl).
- **R11 (Falsifiable Tests and Hand-Written Golden Fixtures)**: Every pipeline invariant and defect fix is verified by falsifiable unit tests in `pipeline/tests/` and hand-authored golden expectations in `pipeline/tests/golden/xx-test-fixture/` (izxl).
- **R12 (Separation of Legal Status and Record Version)**: `legal_status` and `record_version` (`record_supersedes`, `record_superseded_by`, `record_change_reason`) are distinct fields; only current record versions (`record_superseded_by == null`) appear in default UI lists, with `"v2 · corrected from v1"` expanding to version history and never badged as `SUPERSEDED` legal status (izxl).
- **R13 (Text Rights)**: Only documents with `text_rights.mode == "full_text"` have full text published; copyrighted standards (`nbc-2016`) and non-redistributable maps (`aai-cczm`) carry `text_rights.mode == "reference_only"` and publish only citation metadata, cited provisions, and where to obtain them without reproducing their text or height surfaces (izxl).
- **R14 (Explicit Attribution of Derived Work)**: Consolidated `"as amended"` clause records (`consolidated.json`), georeferenced zones (`zones.geojson`), and buffer overlays (`overlays.geojson`) carry `derived: true` and a `method` description, are labelled `"Derived by this project, not an official publication"` in the UI, and link back to the underlying official sources (izxl).

## Design Decisions

### Permissive PDF and Geospatial Stack (R4 Licensing Hygiene)
**Decision**: Use `pypdfium2` (Apache-2.0/BSD-3-Clause) and `Docling` (MIT) with `pdfplumber` (MIT) and `tesseract` (`eng` + `kan`) for PDF parsing, table extraction, and page rasterization, paired with `shapely`, `rasterio`, `pyogrio`, `geopandas`, `opencv-python-headless`, and `scikit-image` for geospatial processing (`docs/decisions/001-parsers-and-licences.md`, `docs/decisions/002-open-data-and-indicodes-practices.md`, `docs/decisions/004-bengaluru-south-parser-and-map-decisions.md`).
**Why**: Complies with Rule R4 by avoiding GPL/AGPL-3.0 and non-commercial libraries or model weights, executes locally without mandatory proprietary API keys, and supports side-by-side parser comparison and Kannada OCR.
**Rejected**: `PyMuPDF` (`fitz`), `Unstract`, `MinerU`, and `Marker` due to GPL/AGPL-3.0 or non-commercial model weight restrictions; `LLMWhisperer` as a required dependency due to proprietary API key requirements.
*Introduced by*: 261123-a5ou-m0-m1-scaffold-schemas-fixture

### Dual-Mode Manifest Fetching in Web Data Client
**Decision**: Centralize all dataset reads in `lib/data.ts`, resolving `NEXT_PUBLIC_MANIFEST_URL` for remote deployments and reading static release artifacts from `public/data/` for Server Components, static generation (`generateStaticParams`), and CI tests.
**Why**: Enables offline development, static route generation, and deterministic CI verification while supporting zero-code-change cloud deployment.
**Rejected**: Hard-coding remote storage URLs in React components or requiring live network requests during unit tests.
*Introduced by*: 261123-a5ou-m0-m1-scaffold-schemas-fixture

### Root Next.js App Layout with `.vercelignore`
**Decision**: Place the Next.js application (`package.json`, `app/`, `components/`, `lib/`, `public/`) directly at the repository root and exclude `pipeline/` via `.vercelignore`.
**Why**: Prevents Vercel's monorepo detector from splitting the repository into separate `web` and `pipeline` deployments or failing with `[PYTHON_ENTRYPOINT_NOT_FOUND]` on `pipeline/pyproject.toml`, ensuring a single `bylaws-india` Vercel deployment.
**Rejected**: Keeping `web/` as a nested subdirectory without root `package.json`, which triggered Vercel's dual `web` + `pipeline` monorepo auto-detection.
*Introduced by*: 261123-a5ou-m0-m1-scaffold-schemas-fixture

### Open-Code (Apache-2.0) and Open-Data (CC BY 4.0) Dual Licensing with Indicodes Rules Practices
**Decision**: License source code under Apache-2.0 (`LICENSE`) and published datasets under CC BY 4.0 (`LICENSE-DATA.md`), and adopt page-bbox citations, `@v<N>` record version chains for verified records, and `declarations.json` coverage gap declarations (`docs/decisions/002-open-data-and-indicodes-practices.md`).
**Why**: Permits unrestricted commercial and civic reuse of both code and structured regulatory data while maintaining verifiable page-level provenance, auditability of record corrections, and explicit disclosure of unmodelled rules.
**Rejected**: Copyleft (`GPL`/`AGPL`) or non-commercial data licences that block downstream civic/commercial integration, or silent omission of unmodelled regulatory documents.
*Introduced by*: 261123-8ay2-m1-5-pipeline-vertical-slice

### Deterministic Repository Root Discovery via Marker File
**Decision**: Resolve the repository root in `pipeline/bylaws/root.py` using explicit `--root <path>`, `BYLAWS_ROOT`, or an upward filesystem walk for `bylaws.toml`.
**Why**: Allows `bylaws` CLI commands and isolated golden tests to execute reliably from any working directory or temporary test root without fragile `__file__` parent-index assumptions.
**Rejected**: Computing the repository root via `Path(__file__).resolve().parents[N]`, which breaks when packages are installed into virtual environments or tested against isolated fixture roots.
*Introduced by*: 261123-8ay2-m1-5-pipeline-vertical-slice

### Immutable Verified Records via In-Array Supersede Chains (Rule R9)
**Decision**: Retain superseded verified records in the published `clauses` and `features` arrays with `record_superseded_by` (and `superseded_by`) set to `<id>@v<N+1>` and append the updated record with `record_id = "<id>@v<N+1>"`, `record_version = N + 1`, `record_supersedes = "<id>@v<N>"`, and `record_change_reason`.
**Why**: Preserves an auditable history of verified clauses and zones directly inside self-contained release files so the web UI can filter superseded record versions out of default lists and surface expandable version history.
**Rejected**: Mutating verified records in place or splitting superseded records into separate sidecar files.
*Introduced by*: 261123-8ay2-m1-5-pipeline-vertical-slice

### Separate Record Version Chain from Legal Status (Rule R12)
**Decision**: Represent record correction history on clauses and zones with `record_version` (integer), `record_supersedes`, `record_superseded_by`, and `record_change_reason`, while reserving `legal_status` (`in_force | draft | superseded | withdrawn | status_unknown`) strictly for regulatory enactment status. Filter superseded record versions (`record_superseded_by != null`) out of default lists and display a compact `"v2 · corrected from v1"` disclosure on the current record.
**Why**: Conflating data correction versions (`1.1@v1` → `1.1@v2`) with repealed legislation (`legal_status: "superseded"`) causes corrected clauses to appear twice and misleads users into thinking an active provision was legally repealed.
**Rejected**: Using a single `SUPERSEDED` badge for both repealed legislation and corrected data records.
*Introduced by*: 261123-izxl-plan-v2-bengaluru-south-complete

### Explicit Text Rights and Derived Work Provenance (Rules R13 & R14)
**Decision**: Add `text_rights: { mode: "full_text" | "reference_only", reason }` to every document and `derived: boolean` + `method: string` to consolidated clause records and geospatial layers. Render `reference_only` documents (`nbc-2016`, `aai-cczm`) as structured citation/metadata hubs without full text, and badge all consolidated clauses and buffered overlays as `"Derived by this project, not an official publication"`.
**Why**: Government statutes, rules, regulations, bye-laws, and gazette notifications may be republished in full under Indian copyright law (Section 52(1)(q) Copyright Act, 1957), whereas BIS standards (NBC 2016) are copyrighted commercial publications and consolidated "as amended" text / buffer polygons are editorial derivations rather than official gazettes.
**Rejected**: Publishing scraped NBC 2016 text (copyright violation) or presenting consolidated text without an explicit derived disclaimer (regulatory traceability violation).
*Introduced by*: 261123-izxl-plan-v2-bengaluru-south-complete

### Server-Side Manifest Filtering via `SHOW_TEST_JURISDICTIONS`
**Decision**: Evaluate `process.env.SHOW_TEST_JURISDICTIONS` (`"true"` or `"1"`) on the server in `lib/data.ts` (`shouldShowTestJurisdictions()`), filter `manifest.jurisdictions` inside `fetchManifest()` / `getVisibleJurisdictions()` by default when `shouldShowTestJurisdictions()` is false, and convert `app/page.tsx` to a Server Component that passes pre-filtered server data to the page.
**Why**: `VERCEL_ENV` is a server-only variable not exposed to client bundles; filtering on the server at build/render time guarantees that production HTML and page props never include `visibility: "test"` jurisdictions.
**Rejected**: Using `NEXT_PUBLIC_VERCEL_ENV` in client components, which still ships test jurisdiction metadata in the client bundle and violates `01-contain-production.md` §2.
*Introduced by*: 261124-tuou-pr-01-contain-production

### Config-Driven Denylist and Provenance Gate via `bylaws check-provenance`
**Decision**: Store the PDF creator/producer denylist (`["fpdf", "pypdf", "reportlab", "structuredbuildingbylaws"]`) in `bylaws.toml` under `[provenance]` and expose `bylaws check-provenance` in `pipeline/bylaws/cli.py` (backed by `pipeline/bylaws/provenance.py`), executed both as a CLI step in `.github/workflows/ci.yml` and via falsifiable unit tests in `pipeline/tests/test_provenance_gate.py`.
**Why**: Keeps the provenance gate configurable without hard-coding tool names in multiple places while failing CI deterministically on any local `source_url`, missing `retrieval` block, or synthetic PDF metadata in non-test jurisdictions.
**Rejected**: Checking provenance only inside `bylaws acquire`, which would not catch hand-committed files or config edits in CI.
*Introduced by*: 261124-fcwm-pr-02-provenance-gate-repo-sync
