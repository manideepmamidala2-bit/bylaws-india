# System Architecture & Core Invariants

**Domain**: architecture

## Overview
`bylaws-india` (**Bylaw One** — `"Bengaluru's building rules. One code."`) is an open-code (Apache-2.0) and open-data (CC BY 4.0) machine-readable dataset, consolidated building code, and plain-language web viewer for Indian building and municipal bylaws (a5ou, 8ay2, izxl, tuou, peq2, 4e7t, ucy1, bups, jqph). The repository is split into an offline Python 3.12+ data pipeline (`pipeline/`) and a read-only Next.js web application at the repository root (`app/`, `components/`, `lib/`, `public/`, with `.vercelignore` excluding `pipeline/` so Vercel deploys a single `bylaws-india` project), connected strictly through fifteen versioned JSON and GeoJSON data contracts at Unified Schema `1.4` defined in [data-contracts](/schemas/data-contracts.md) (a5ou, 8ay2, izxl, 4e7t, ucy1). Release `4.0.0` publishes the parent Greater Bengaluru jurisdiction (`in-ka-bengaluru`) and five child City Corporations (`in-ka-bengaluru-central`, `-north`, `-south`, `-east`, `-west`) with single-source shared document, parameter, and provision deduplication, thin City Corporation diff layers verified by a 5-corporation CI parity check (`pipeline/tests/test_pr12_greater_bengaluru.py`), per-chapter `<doc_id>.outline.json` + `<doc_id>/chapters/<chapter_eid>.json` payloads, machine-enforced verbatim provision and home-page FAR story excerpt text fidelity (`pipeline/bylaws/fidelity.py`, `pipeline/tests/test_text_fidelity.py`), separated `notes_by_site` and `summary_by_site`, explicit `instrument_type` classification, full consolidated code, 314 deduplicated and supersession-resolved building parameter records (`parameters.json`) with per-parameter plausibility bounds, hectare-to-`m²` interval normalization, non-FAR row exclusion, CI parameter overlap and band continuity checks (`check_parameter_overlaps`, `check_band_continuity`), and sentence parking prose, a 6-step deterministic statutory plot resolver (`jurisdictions/resolution.yaml`, `pipeline/bylaws/resolver.py`, `lib/resolver.ts`), and rebuilt legal relations (`relations.json`), while keeping large generated Bengaluru payloads and `basemap.pmtiles` out of git in HTTP `206` range-request and CORS-verified storage (peq2, 4e7t, ucy1, bups, jqph). In `public/data/manifest.json`, the synthetic release `1.0.0` of Bengaluru South City Corporation (`in-ka-bengaluru-south`, `visibility: "public"`) remains recorded as `status: "withdrawn"` (`withdrawn_reason: "Synthetic demonstration data, not the law of Bengaluru South"`), while the synthetic offline fixture (`xx-test-fixture` release `0.1.0`, `visibility: "test"`) is tracked in git and filtered out on the server unless `SHOW_TEST_JURISDICTIONS` is enabled (a5ou, 8ay2, izxl, tuou, 4e7t, ucy1).

## Requirements

### Requirement: Two-Half Architecture, Repository Root Discovery, Out-of-Git Range Storage, and Open-Data Governance
The repository MUST maintain a strict boundary between the local Python processing pipeline (`pipeline/`, pinned to Python `3.12` via `.python-version` and `pipeline/.python-version`) and the read-only Next.js web viewer at the repository root (`app/`, `components/`, `lib/`, `public/`), sharing declarative jurisdiction configurations in `jurisdictions/` and JSON Schemas in `schemas/` (a5ou, 8ay2, 4e7t). Repository root discovery (`resolve_repo_root()` in `pipeline/bylaws/root.py`) MUST resolve the repository root deterministically in priority order: `--root <path>` CLI option on `bylaws`, `BYLAWS_ROOT` environment variable, or an upward directory walk from `Path.cwd()` for the `bylaws.toml` root marker file, raising `click.ClickException` if none is found (8ay2). Working directories `data/raw/`, `data/interim/`, and `data/processed/`, as well as generated Bengaluru release payloads (`public/data/in-ka-bengaluru*`, `~248 MB`) and `basemap.pmtiles` (`33 MB`), MUST be excluded from git tracking via `.gitignore` and served from HTTP range-request (`206 Partial Content`) and CORS-enabled (`Access-Control-Allow-Origin`, `Access-Control-Expose-Headers: Content-Range, Content-Length, Accept-Ranges`) storage (`pipeline/bylaws/storage.py`, `scripts/sync_storage.py`, verified by `pipeline/tests/test_range_storage.py`), whereas `public/data/xx-test-fixture/`, `public/data/manifest.json`, manual curation files in `data/overrides/<jurisdiction>/`, verification reports in `data/reports/<jurisdiction>/`, owner precision review sheets in `docs/review/relations-labelling.md`, human-readable source registers in `docs/sources/<jurisdiction>.md`, architecture decisions in `docs/decisions/`, and open-data governance files (`LICENSE` under Apache-2.0, `LICENSE-DATA.md` under CC BY 4.0 with attribution to `"Structured Building Bylaws"`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `CITATION.cff`, `docs/dependencies.md`, `docs/data-sources.md`, `docs/plan-v2.md`, `docs/plans/building-code-plan.md`, `docs/plans/bylaw-one-clean-ui-plan.md`, and `docs/progress.md` recording the pending domain and trademark check for `"Bylaw One"`) MUST be tracked in version control (a5ou, 8ay2, izxl, 4e7t, bups).

### Requirement: Core Engineering Rules (Rules R1–R16)
All pipeline stages and web components MUST uphold the sixteen non-negotiable engineering and legal invariants (a5ou, 8ay2, izxl, fcwm, 4e7t):
- **R1 (Zero Jurisdiction Hard-Coding)**: Jurisdiction-specific metadata resides exclusively in `jurisdictions/<id>.yaml`, `jurisdictions/resolution.yaml`, and `data/overrides/<jurisdiction>/` (a5ou, 8ay2, izxl, 4e7t).
- **R2 (Mandatory Provenance)**: Every clause carries `doc_id`, `citations` (with 1-based `page`, normalized `[x0, y0, x1, y1]` `bbox`, and `text_excerpt`), and `verification`; every parameter record carries cell-level `source` (`doc_id`, `eid`, `table_eid`, `row_index`, `col_index`, `column_header`, `row_header`, `cell_text`, `page`, `bbox`, `official_url`, `archive_url`); every zone feature carries `source_map`, `georef_run`, `extraction_method`, `source_attribution`, and `verification`; every clause–zone tag carries a quoted `reason` (a5ou, 8ay2, izxl, 4e7t).
- **R3 (Explicit Legal Status)**: Documents, clause trees, clauses, and parameter records carry an explicit `legal_status` (`in_force | draft | superseded | withdrawn | status_unknown`), and `draft` artifacts are published separately from `in_force` regulations, excluded by Step 1 of `resolution.yaml`, and badged in the UI (a5ou, 8ay2, izxl, 4e7t).
- **R4 (Strict Permissive-Only Licensing)**: All Python distributions and direct + transitive npm packages in `package-lock.json` / `node_modules` are restricted to the explicit permissive allowlist (`MIT`, `Apache-2.0`, `BSD-2-Clause`, `BSD-3-Clause`, `BSD`, `ISC`, `PSF-2.0`, `0BSD`, `CC0-1.0`, `Unlicense`, `OFL-1.1`, `MPL-2.0`, plus documented `LGPL` runtime library imports in `docs/dependencies.md`); `GPL`, `GPLv3`, `AGPL` (`PyMuPDF`, `Unstract`, `MinerU`, `Marker`), `UNKNOWN`, and empty licences are rejected by `pipeline/tests/test_r4_licences.py` in CI (a5ou, 8ay2, izxl).
- **R5 (Immutable Raw Sources)**: Downloaded files in `data/raw/` are never modified in place and are verified via SHA-256 checksums in `<doc_id>.meta.json` (a5ou, 8ay2).
- **R6 (Deterministic Reproducibility)**: Generated files in `data/processed/` are never hand-edited; all manual corrections, zone tags, and map curations are committed under `data/overrides/<jurisdiction>/*.yaml`, and all generated timestamps (`retrieved_at`, `generated`, `released_at`, ZIP member timestamps) derive deterministically from `SOURCE_DATE_EPOCH` so repeated runs produce byte-identical outputs and `.zip` archives (a5ou, izxl).
- **R7 (Fail Loudly)**: Unreadable manifests, unknown `map_id` curations, missing CRS metadata, and validation failures raise `click.ClickException` or `ValueError` and exit non-zero (8ay2, izxl).
- **R8 (No Defaults That Strengthen a Claim)**: Neither the pipeline nor the web UI supplies fallback defaults for missing regulatory status or source pages; missing or contested status renders `STATUS UNKNOWN` in `StatusBadge`, and a clause without a citation page renders `"No source page recorded"` without an anchor link (8ay2, izxl).
- **R9 (Immutable Verified Records)**: Verified records (`human_verified` or `machine_checked` when versioned) are never mutated in place by `apply-overrides`; when an override changes a verified clause or zone, the existing `<id>@v<N>` record is retained with `record_superseded_by` (and `superseded_by`) set to `<id>@v<N+1>` and a new `<id>@v<N+1>` record is appended with `record_version = N + 1`, `record_supersedes = "<id>@v<N>"`, and `record_change_reason` (8ay2, izxl).
- **R10 (Honest Verification)**: Agent-verified records are marked `machine_checked` (or `unverified` before check); zero records are marked `human_verified` by automated pipelines (izxl, 4e7t).
- **R11 (Falsifiable Tests and Hand-Written Golden Fixtures)**: Every pipeline invariant, parameter parser rule, and plot resolver target is verified by falsifiable unit tests in `pipeline/tests/` and `__tests__/`, plus hand-authored golden expectations in `pipeline/tests/golden/xx-test-fixture/` (izxl, 4e7t).
- **R12 (Separation of Legal Status and Record Version)**: `legal_status` and `record_version` (`record_supersedes`, `record_superseded_by`, `record_change_reason`) are distinct fields; only current record versions (`record_superseded_by == null`) appear in default UI lists, with `"v2 · corrected from v1"` expanding to version history and never badged as `SUPERSEDED` legal status (izxl).
- **R13 (Text Rights)**: Only documents with `text_rights.mode == "full_text"` have full text published; copyrighted standards (`nbc-2016`) and non-redistributable maps (`aai-cczm`) carry `text_rights.mode == "reference_only"` and publish only citation metadata, cited provisions, and where to obtain them without reproducing their text or height surfaces (izxl).
- **R14 (Explicit Attribution of Derived Work)**: Consolidated `"as amended"` documents (`consolidated.json` and per-chapter snapshots), extracted parameter records (`parameters.json`), statutory resolution rules (`resolution.yaml`), georeferenced zones (`zones.geojson`), and buffer overlays (`overlays.geojson`) carry `derived: true` and a `method` / notice description, are labelled as derived work in the UI, and link back to the underlying official sources (izxl, 4e7t).
- **R15 & R16 (Retrieval Provenance and Synthetic PDF Denylist)**: Every acquired non-test source carries an HTTP `retrieval` record with Wayback Machine archive snapshot metadata, and non-test PDFs matching the `bylaws.toml` creator/producer denylist are rejected by `bylaws check-provenance` (fcwm).

## Design Decisions

### Permissive PDF and Geospatial Stack (R4 Licensing Hygiene)
**Decision**: Use `pypdfium2` (Apache-2.0/BSD-3-Clause) and `Docling` (MIT) with `pdfplumber` (MIT) and `tesseract` (`eng` + `kan`) for PDF parsing, table extraction, and page rasterization, paired with `shapely`, `rasterio`, `pyogrio`, `geopandas`, `opencv-python-headless`, and `scikit-image` for geospatial processing (`docs/decisions/001-parsers-and-licences.md`, `docs/decisions/002-open-data-and-indicodes-practices.md`, `docs/decisions/004-bengaluru-south-parser-and-map-decisions.md`).
**Why**: Complies with Rule R4 by avoiding GPL/AGPL-3.0 and non-commercial libraries or model weights, executes locally without mandatory proprietary API keys, and supports side-by-side parser comparison and Kannada OCR.
**Rejected**: `PyMuPDF` (`fitz`), `Unstract`, `MinerU`, and `Marker` due to GPL/AGPL-3.0 or non-commercial model weight restrictions; `LLMWhisperer` as a required dependency due to proprietary API key requirements.
*Introduced by*: 261123-a5ou-m0-m1-scaffold-schemas-fixture

### Dual-Mode Manifest Fetching in Web Data Client
**Decision**: Centralize all dataset reads in `lib/data.ts`, resolving `NEXT_PUBLIC_MANIFEST_URL` for remote deployments and reading static release artifacts from `public/data/` for Server Components, static generation (`generateStaticParams`), and CI tests.
**Why**: Enables offline development, static route generation, and deterministic CI verification while supporting zero-code-change cloud deployment.
**Rejected**: Hard-coding remote storage URLs in React components or requiring live network requests during unit tests.
*Introduced by*: 261123-a5ou-m0-m1-scaffold-schemas-fixture

### Root Next.js App Layout with `.vercelignore`
**Decision**: Place the Next.js application (`package.json`, `app/`, `components/`, `lib/`, `public/`) directly at the repository root and exclude `pipeline/` via `.vercelignore`.
**Why**: Prevents Vercel's monorepo detector from splitting the repository into separate `web` and `pipeline` deployments or failing with `[PYTHON_ENTRYPOINT_NOT_FOUND]` on `pipeline/pyproject.toml`, ensuring a single `bylaws-india` Vercel deployment.
**Rejected**: Keeping `web/` as a nested subdirectory without root `package.json`, which triggered Vercel's dual `web` + `pipeline` monorepo auto-detection.
*Introduced by*: 261123-a5ou-m0-m1-scaffold-schemas-fixture

### Open-Code (Apache-2.0) and Open-Data (CC BY 4.0) Dual Licensing with Indicodes Rules Practices
**Decision**: License source code under Apache-2.0 (`LICENSE`) and published datasets under CC BY 4.0 (`LICENSE-DATA.md`), and adopt page-bbox citations, `@v<N>` record version chains for verified records, and `declarations.json` coverage gap declarations (`docs/decisions/002-open-data-and-indicodes-practices.md`).
**Why**: Permits unrestricted commercial and civic reuse of both code and structured regulatory data while maintaining verifiable page-level provenance, auditability of record corrections, and explicit disclosure of unmodelled rules.
**Rejected**: Copyleft (`GPL`/`AGPL`) or non-commercial data licences that block downstream civic/commercial integration, or silent omission of unmodelled regulatory documents.
*Introduced by*: 261123-8ay2-m1-5-pipeline-vertical-slice

### Deterministic Repository Root Discovery via Marker File
**Decision**: Resolve the repository root in `pipeline/bylaws/root.py` using explicit `--root <path>`, `BYLAWS_ROOT`, or an upward filesystem walk for `bylaws.toml`.
**Why**: Allows `bylaws` CLI commands and isolated golden tests to execute reliably from any working directory or temporary test root without fragile `__file__` parent-index assumptions.
**Rejected**: Computing the repository root via `Path(__file__).resolve().parents[N]`, which breaks when packages are installed into virtual environments or tested against isolated fixture roots.
*Introduced by*: 261123-8ay2-m1-5-pipeline-vertical-slice

### Immutable Verified Records via In-Array Supersede Chains (Rule R9)
**Decision**: Retain superseded verified records in the published `clauses` and `features` arrays with `record_superseded_by` (and `superseded_by`) set to `<id>@v<N+1>` and append the updated record with `record_id = "<id>@v<N+1>"`, `record_version = N + 1`, `record_supersedes = "<id>@v<N>"`, and `record_change_reason`.
**Why**: Preserves an auditable history of verified clauses and zones directly inside self-contained release files so the web UI can filter superseded record versions out of default lists and surface expandable version history.
**Rejected**: Mutating verified records in place or splitting superseded records into separate sidecar files.
*Introduced by*: 261123-8ay2-m1-5-pipeline-vertical-slice

### Separate Record Version Chain from Legal Status (Rule R12)
**Decision**: Represent record correction history on clauses and zones with `record_version` (integer), `record_supersedes`, `record_superseded_by`, and `record_change_reason`, while reserving `legal_status` (`in_force | draft | superseded | withdrawn | status_unknown`) strictly for regulatory enactment status. Filter superseded record versions (`record_superseded_by != null`) out of default lists and display a compact `"v2 · corrected from v1"` disclosure on the current record.
**Why**: Conflating data correction versions (`1.1@v1` → `1.1@v2`) with repealed legislation (`legal_status: "superseded"`) causes corrected clauses to appear twice and misleads users into thinking an active provision was legally repealed.
**Rejected**: Using a single `SUPERSEDED` badge for both repealed legislation and corrected data records.
*Introduced by*: 261123-izxl-plan-v2-bengaluru-south-complete

### Explicit Text Rights and Derived Work Provenance (Rules R13 & R14)
**Decision**: Add `text_rights: { mode: "full_text" | "reference_only", reason }` to every document and `derived: boolean` + `method: string` to consolidated clause records and geospatial layers. Render `reference_only` documents (`nbc-2016`, `aai-cczm`) as structured citation/metadata hubs without full text, and badge all consolidated clauses and buffered overlays as `"Derived by this project, not an official publication"`.
**Why**: Government statutes, rules, regulations, bye-laws, and gazette notifications may be republished in full under Indian copyright law (Section 52(1)(q) Copyright Act, 1957), whereas BIS standards (NBC 2016) are copyrighted commercial publications and consolidated "as amended" text / buffer polygons are editorial derivations rather than official gazettes.
**Rejected**: Publishing scraped NBC 2016 text (copyright violation) or presenting consolidated text without an explicit derived disclaimer (regulatory traceability violation).
*Introduced by*: 261123-izxl-plan-v2-bengaluru-south-complete

### Server-Side Manifest Filtering via `SHOW_TEST_JURISDICTIONS`
**Decision**: Evaluate `process.env.SHOW_TEST_JURISDICTIONS` (`"true"` or `"1"`) on the server in `lib/data.ts` (`shouldShowTestJurisdictions()`), filter `manifest.jurisdictions` inside `fetchManifest()` / `getVisibleJurisdictions()` by default when `shouldShowTestJurisdictions()` is false, and convert `app/page.tsx` to a Server Component that passes pre-filtered server data to the page.
**Why**: `VERCEL_ENV` is a server-only variable not exposed to client bundles; filtering on the server at build/render time guarantees that production HTML and page props never include `visibility: "test"` jurisdictions.
**Rejected**: Using `NEXT_PUBLIC_VERCEL_ENV` in client components, which still ships test jurisdiction metadata in the client bundle and violates `01-contain-production.md` §2.
*Introduced by*: 261124-tuou-pr-01-contain-production

### Config-Driven Denylist and Provenance Gate via `bylaws check-provenance`
**Decision**: Store the PDF creator/producer denylist (`["fpdf", "pypdf", "reportlab", "structuredbuildingbylaws"]`) in `bylaws.toml` under `[provenance]` and expose `bylaws check-provenance` in `pipeline/bylaws/cli.py` (backed by `pipeline/bylaws/provenance.py`), executed both as a CLI step in `.github/workflows/ci.yml` and via falsifiable unit tests in `pipeline/tests/test_provenance_gate.py`.
**Why**: Keeps the provenance gate configurable without hard-coding tool names in multiple places while failing CI deterministically on any local `source_url`, missing `retrieval` block, or synthetic PDF metadata in non-test jurisdictions.
**Rejected**: Checking provenance only inside `bylaws acquire`, which would not catch hand-committed files or config edits in CI.
*Introduced by*: 261124-fcwm-pr-02-provenance-gate-repo-sync

### Greater Bengaluru Parent-Child Jurisdiction Hierarchy and Shared Bundle Reference
**Decision**: Model Greater Bengaluru with a parent jurisdiction (`in-ka-bengaluru`) holding shared documents, amendment links, and city-wide 5-corporation/369-ward boundaries, and five child City Corporations (`in-ka-bengaluru-central`, `-north`, `-south`, `-east`, `-west` with `parent: "in-ka-bengaluru"`) that inherit shared parent documents, apply corporation-specific 2026 Building (Amendment) Bye-laws via `applies_in`, and reference unamended shared document bundles from `/data/in-ka-bengaluru/<version>/` in `manifest.json`.
**Why**: Enables per-corporation consolidated views of `bbl-2003` and corporation-specific ward/zone maps while avoiding 6-way duplication of large unamended reference bundles (`ka-model-bbl-2017`) in git and Vercel static deployments.
**Rejected**: Duplicating all 24 `.clauses.json` files across all 6 jurisdiction release folders, which would exceed Vercel's static deployment size limit.
*Introduced by*: 261124-peq2-pr-12-greater-bengaluru-overnight

### Unified Schema 1.4 and Per-Chapter Content-Addressed Storage
**Decision**: Unify all JSON Schemas (`schemas/*.schema.json`) to `schema_version: "1.4"`, add `parameters.schema.json` and `resolution.schema.json`, store shared base/amendment documents once in the parent `in-ka-bengaluru` store, and split large clause trees and consolidated documents into `<doc_id>.outline.json` + per-chapter `<doc_id>/chapters/<chapter_eid>.json` files.
**Why**: Eliminates schema version drift (`1.2` vs `1.3` vs `1.4`), avoids 6-way corporation duplication of base documents, and cuts document page HTML payloads from ~12 MB to `< 300 KB` (`<= 1.5 MB` initial JS + data).
**Rejected**: Shipping monolithic multi-megabyte `.clauses.json` payloads into SSR HTML or maintaining per-corporation copies of unchanged base documents.
*Introduced by*: 261125-4e7t-bengaluru-building-code-plan

### Statutory Incorporation (`incorporates`) and Declarative 6-Step Resolution (`resolution.yaml`)
**Decision**: Model `bbl-2003` Bye-law `1.4` (inserted 2017) as an `incorporates` relation to `rmp2015-zr` for use, coverage, FAR, setbacks, height, floors, dwelling units, and parking, and resolve multi-instrument parameters deterministically through the 6 cited steps in `jurisdictions/resolution.yaml` shared between `pipeline/bylaws/resolver.py` and `lib/resolver.ts`.
**Why**: Accurately reflects Indian municipal law (incorporation by reference rather than textual repeal/substitution of `bbl-2003`), preserves both consolidated texts, and ensures every plot parameter answer cites a deterministic statutory priority step or honestly reports `"Not settled: two rules apply"`.
**Rejected**: Treating `rmp2015-zr` as textually substituting `bbl-2003` clauses or using heuristic word/number matching to flag unresolved conflicts.
*Introduced by*: 261125-4e7t-bengaluru-building-code-plan

### Verbatim Legal Text with Stand-Off Site Notes and Recorded OCR Corrections
**Decision**: Enforce in `pipeline/bylaws/fidelity.py` and CI (`pipeline/tests/test_text_fidelity.py`) that every provision's text matches the parser's text of its cited page(s) after whitespace normalization, or is covered by a recorded `ocr_correction` (`{ original_text, corrected_text, page, reason }`) or `"[unreadable in source]"` token; move all editorial explanations, notification numbers, and summaries into `notes_by_site` (`"Note by this site"`) and `summary_by_site` (`"In short (by this site)"`).
**Why**: Legal provisions must quote the official gazette/document verbatim so readers can rely on the exact words of the law while still benefiting from clearly separated plain-language notes and transparent OCR fixes.
**Rejected**: Inserting bracketed editorial notes (`[Per UDD 14 TTP 2017...]`) or table digests directly inside clause prose, which corrupts legal quotes and makes machine text-fidelity verification impossible.
*Introduced by*: 261125-ucy1-trustworthy-simple-building-code

### Explicit Instrument Types and Plain-Language Progressive Disclosure
**Decision**: Classify every register entry by `instrument_type` (`instrument | compilation | map | bill | order`) so compilations, maps, and bills never appear as in-force instruments, and structure every web page with a plain-language primary layer (most-recent-first lists, law-order provisions showing only number and verbatim text, subject pages starting with `"What applies today"`) and tap-to-expand technical/legal details.
**Why**: Homeowners and small builders need immediate, jargon-free answers and clear legal statuses first, while architects and lawyers can tap any provision to inspect exact citations, version history, resolution steps, and technical metadata.
**Rejected**: Rendering internal schema versions, `eid`s, enum strings (`sq_m`, `state_rules`), and repeated metadata badges inline on every provision row.
*Introduced by*: 261125-ucy1-trustworthy-simple-building-code

### Narrative Home Page with Five-Step Verbatim FAR Story Instead of Map-First Home
**Decision**: Replace the map-first home page and plot calculator on `/` with a single-scroll editorial page in the `dg2n.com` idiom anchored by a 5-step FAR chronology (`2004`, `2007`, `2017`, `2025`, `Today`) quoting verbatim official text with page links, while moving the interactive map to `/j/[id]` (linked from the footer and the `Land use` subject) and removing plot inputs from all views.
**Why**: Explains the project's core value—how scattered bye-laws, master plan zoning rules, 2017 incorporation (bye-law 1.4), and 2025 premium FAR combine into one traceable code—before asking readers to navigate tables or maps, and avoids presenting plot-level answers while parameter tables are being reviewed as clean subject tables first.
**Rejected**: Keeping the full-viewport MapLibre map and Plot Card calculator on the home page, which obscured the statutory structure and surfaced raw parameter rows before table cleanup.
*Introduced by*: 261126-bups-bylaw-one-clean-ui

### Parameter Plausibility Bounds, Hectare Normalization, and Non-FAR Row Exclusion
**Decision**: Enforce per-parameter numeric plausibility bounds (`far_base_max` `0.25–5.0`, `far_premium_additional_max` `0.05–2.0`, `ground_coverage_max_pct` `5–100%`, `setback_*_min_m` `0–30 m`, `building_height_max_m` `3–250 m`, `floors_max` `1–60`), multiply hectare plot-area intervals by `10,000` to normalize to `m²`, and exclude deviation tolerance, compounding-fee, and premium FAR price rows from FAR parameter records, logging any out-of-bounds candidates to `data/reports/<jurisdiction>/parameter-mismatches.md`.
**Why**: Prevents unit misreads (`0.40 Hectares` read as `0.4 m²`) and fee/tolerance percentages (`10%`, `20%`, `50%`) from appearing as implausible FAR or plot-size values in subject tables.
**Rejected**: Displaying unfiltered regex-extracted numbers in subject tables or silently dropping out-of-bounds rows without an owner review report.
*Introduced by*: 261126-bups-bylaw-one-clean-ui

### Parameter Supersession, Duplicate Collapsing, and Band Continuity Reporting in `parameters.py`

**Why**: Keeps the web application read-only and deterministic while ensuring that `parameters.json` consumers, CI checks, and subject tables all see the exact same governing vs. superseded state and unadjusted statutory band overlaps.
**Rejected**: Filtering superseded or duplicate rows ad-hoc only in React components or silently altering `11.5 m` to `12.0 m` in Table 9.

### Structured `applicability_rules` for Settled Table Transitions
**Decision**: Record in-force applicability clauses (`rmp2015-zr` `3.1(ii)` and `3.1(iii)` as substituted in January 2026) in `parameters.json` `applicability_rules`, surface a one-line explanation (`"Buildings up to 12 m use Table 8; taller buildings use Table 9 (clauses 3.1(ii) and (iii), January 2026)."`) with tap-to-open verbatim quotes under `"Why this rule applies"` and a small unreachable-band note on `Table 9`'s `11.5–12 m` row, and show `"Not settled: two rules apply"` only when no in-force clause decides.
**Why**: Distinguishes an apparent table-header overlap (`Table 8` `<= 12 m` vs `Table 9` `> 11.5 m`) that is explicitly settled by the governing text (`3.1(ii)` and `3.1(iii)`) from a genuine statutory conflict where no in-force clause decides.
**Rejected**: Altering the printed `11.5 m` number in `Table 9` or displaying a false `"Not settled"` warning when `3.1(ii)` and `3.1(iii)` settle the boundary.
*Introduced by*: 261126-mspg-one-build-correct-citations

### Committed Compressed Page-Text Store with SHA-256 Checksum Integrity (`data/page_text/`)
**Decision**: Store the extracted per-page text of every acquired PDF instrument alongside its 64-character lowercase hex `sha256` checksum in versioned gzipped JSON files (`data/page_text/<doc_id>.pages.json.gz`, plus `data/page_text/xx-test-fixture/<doc_id>.pages.json.gz`), remove the `.clauses.json` fallback and neighbor-page padding from `pipeline/bylaws/fidelity.py`, and fail `verify_jurisdiction_text_fidelity` whenever a cited document's page-text store is missing, a cited page number is absent, or the stored `sha256` disagrees with the source register's `retrieval.sha256` / `.meta.json` `sha256`.
**Why**: Rebuilding page word tokens from published `.clauses.json` files in CI made the citation check self-referential and unable to fail in CI; committing compressed per-page text tied to the PDF's cryptographic checksum makes the citation check independent, fast, and falsifiable in CI.
**Rejected**: Rebuilding page tokens from `.clauses.json` in CI or committing multi-hundred-megabyte uncompressed `data/raw/` PDFs into git.
*Introduced by*: 261126-3t3i-trust-and-accuracy

### Verification-Report-Driven Map Positional Accuracy and Sheet-Fitting Error Separation
**Decision**: Parse the measured street centre-line offset metrics (`road_median_offset_m` and `road_p90_offset_m`) alongside the affine grid-fit RMSE (`grid_fit_rmse_m`) from `data/reports/<id>/map-verification.md` and `geo-layers.json`, generate the map page's primary accuracy statement dynamically from the median and 90th-percentile street offsets (`"Zone boundaries are approximate: typically about 8 m from street centre-lines, and within about 21 m in 9 out of 10 places."`), and move the `0.0032 m` grid-fit RMSE inside `Details` explicitly labelled as the sheet-fitting error.
**Why**: `0.0032 m` (`3.2 mm`) measures how closely the 20 printed `+` UTM grid crosshairs fit an affine transform on the vector PDF sheet, whereas the independent OpenStreetMap street centre-line check in `map-verification.md` measures a median offset of `8.02 m` and a 90th-percentile offset of `21.11 m`.
**Rejected**: Displaying `accuracy_m: 0.0032` as street centre-line accuracy or hard-coding `8 m` and `21 m` as literals in JSX without generating them from the verification report data.
*Introduced by*: 261126-3t3i-trust-and-accuracy

### Honest Statutory Plot Resolver Outcomes Without Assumed Dimensions
**Decision**: Remove the `3:2` plot ratio (`inferred_depth`, `inferred_width`) and `11.5 m` building height defaults from `pipeline/bylaws/resolver.py` and `lib/resolver.ts`, return `"needs depth"` / `"needs width"` / `"needs height"` (`status: "needs_depth" | "needs_width" | "needs_height"`) whenever a rule depends on an omitted dimension, and split `"no_applicable_rule"` into `"No limit in the law for this case"` (`status: "no_limit_in_law"`, carrying the governing citation and quote from `no_limit_in_law_rules`) and `"Not covered by our data yet"` (`status: "not_covered_by_data"`).
**Why**: Fabrication of plot depth, plot width, or building height violates Constitution Principle I and Rule R8, and returning a single `"No rule matched"` conflates statutory absence of a cap with unmodelled data gaps.
**Rejected**: Defaulting missing dimensions to a `3:2` aspect ratio and `11.5 m` height or returning an undifferentiated `"No rule matched plot inputs"` string.
*Introduced by*: 261126-3t3i-trust-and-accuracy
