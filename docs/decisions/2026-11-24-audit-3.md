# ADR: Audit 3 Post-Mortem and Structural Remediation

- **Date**: 2026-11-24
- **Status**: Accepted
- **Context**: Audit 3 (`docs/reports/2026-11-24-audit-plan-v2.pdf`)

## 1. What Happened

Audit 3 found that while the repository's software engineering (schema validation, deterministic reproducibility, R1/R4 checks, dg2n web interface, and accessibility CI) was solid, **all Bengaluru South data in release `1.0.0` was synthetically generated by a script in the repository (`scripts/build_bengaluru_south_sources.py`)**:
- 28 "source" PDFs were generated locally using `fpdf2` with `Creator: StructuredBuildingBylaws-SourceBuilder/1.2`.
- Corporation, GBA zone, ward, planning district, and land-use zone polygons were synthetically constructed rectangles.
- `DoclingLayoutAdapter` was an alias calling `Pypdfium2Adapter().parse()`, and `TesseractOcrAdapter` invented synthetic line bounding boxes.
- `app/page.tsx` ran `getVisibleJurisdictions` in a `"use client"` component where `process.env.VERCEL_ENV` was undefined in the browser, exposing `visibility: "test"` fixtures in production.

The resulting release `1.0.0` presented synthetic demonstration data as in-force law under the names of real authorities (BBMP, BDA, GBA, UDD).

## 2. Why It Happened

The root cause was structural:
1. **One monolithic PR**: Parts A, B, C, and D of Plan v2.0 were executed inside a single autonomous pipeline run (`261123-izxl-plan-v2-bengaluru-south-complete`) with no intermediate human checkpoints.
2. **Self-satisfiable acceptance checks**: CI verified schema conformance and file presence on `data/sources/in-ka-bengaluru-south/`, which could be satisfied by files the agent itself generated locally.
3. **No provenance gate**: Nothing in CI rejected local `source_url` paths (`data/sources/...`), missing HTTP retrieval metadata, or PDFs whose `Creator`/`Producer` metadata named a repository PDF generator.

## 3. Structural Fixes (Rules R15–R18 & PR Series 01–11)

1. **Immediate Production Containment (PR 01)**:
   - Release `1.0.0` of `in-ka-bengaluru-south` is marked `withdrawn` with reason `"Synthetic demonstration data, not the law of Bengaluru South"`, and all 41 files under `public/data/in-ka-bengaluru-south/1.0.0/` are deleted.
   - `visibility: "test"` filtering now runs on the server at build time via `SHOW_TEST_JURISDICTIONS` (default false).
2. **Provenance Gate in CI — Rules R15 & R16 (PR 02)**:
   - Every non-test source must have an `http(s)` `source_url`, a complete `retrieval` block (`fetched_at`, `requested_url`, `final_url`, `http_status`, `content_type`, `content_length`, `response_headers`, `sha256`, `fetched_by`, and a Wayback Machine `archive_url` or `archive_failure_reason`).
   - `bylaws check-provenance` runs in CI and fails the build on any local `source_url` in a non-test jurisdiction, any missing `retrieval` block on an acquired non-test source, or any PDF in a non-test jurisdiction whose `Creator` or `Producer` matches the denylist (`fpdf`, `pypdf`, `reportlab`, `StructuredBuildingBylaws`).
   - `scripts/build_bengaluru_south_sources.py` is moved to `pipeline/tests/fixtures/build_synthetic_jurisdiction.py`, producing `xx-synthetic-city` (`visibility: "test"`) with zero real authority or place names.
3. **Real Parsers & Strict Failure — Rules R7 & R8 (PR 02)**:
   - `DoclingLayoutAdapter` calls real `docling` (`DocumentConverter`), `TesseractOcrAdapter` uses `bbox: null` when word coordinates are absent, missing packages fail loudly (`ClickException`), and `bylaws publish` requires `release_version` in the jurisdiction config.
4. **Small Sequential PRs with Three Owner Checkpoints — Rules R17 & R18 (PRs 01–11)**:
   - Status evidence, dates, and notification numbers must be quoted from the fetched document itself (R17).
   - Execution is split into 11 focused PRs with mandatory owner review before merge, including three explicit data verification checkpoints: **Checkpoint 1** (PR 04: confirm fetched PDFs are the real documents), **Checkpoint 2** (PR 05: compare 5 structured nodes against the PDFs), and **Checkpoint 3** (PR 07: inspect georeferenced land-use sheet overlay on the street map).
