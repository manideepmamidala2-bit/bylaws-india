# Structured Building Bylaws (`bylaws-india`)

Structured Building Bylaws is an open-source pipeline (`pipeline/`) and web viewer (`app/`, `components/`, `lib/`) that converts municipal building bye-laws, master plan zoning regulations, building-relevant statutory provisions, and official land-use maps in India into schema-validated, citable data with page and bounding-box provenance.

## Current Status

- **Release `1.0.0` (Withdrawn)**: The initial Bengaluru South City Corporation (`in-ka-bengaluru-south`) release `1.0.0` was synthetically generated by a script in the repository during pipeline development and was not the law of Bengaluru South. It has been withdrawn and removed from `public/data/`.
- **Real Acquisition Under Way**: Real source documents and official maps for Bengaluru South City Corporation are being acquired from official origins with full HTTP retrieval records and Wayback Machine archive snapshots across the PR 01–11 series (`docs/plans/pr-series/`).
- **What Is Published Today**: `in-ka-bengaluru-south` is listed on the public site with status `"No data published yet"` and `1.0.0` marked withdrawn. Real releases begin at `2.0.0` (PR 05) once the core documents are acquired and verified at Owner Checkpoints 1 and 2.

## Scope & Inclusion Test

Every document or provision is evaluated against a single inclusion test (see [`docs/scope.md`](docs/scope.md)):

> **Does it decide what can be built on a plot, or what a building must comply with to be approved and occupied?**

| Tier | What | Treatment |
|------|------|-----------|
| **Core** | Building Bye-laws 2003 and every amendment (including the 2026 Bengaluru South City Corporation amendment); RMP 2015 Zoning Regulations and every amendment; RMP 2015 land-use maps for Bengaluru South | Structured completely |
| **Supporting** | Building-relevant provisions of other instruments: fire NOC (buildings 21 m and above), TDR rules affecting usable FAR, occupancy certificate exemption orders, metro influence zone, verified lake buffers | Only the building-relevant provisions structured; linked to the full instrument |
| **Register only** | Whole Acts beyond their building provisions; procedural circulars; National Building Code (copyrighted by BIS) | Listed with links; not structured |

**English only**: Any building instrument that exists only in Kannada is listed in the register with a declared gap.

## Installation & Quickstart (`make setup`)

### System Prerequisites

Install Python 3.12+, Node.js 22+, `uv`, Tesseract OCR, and GDAL:

```bash
# Ubuntu / Debian
sudo apt-get update && sudo apt-get install -y tesseract-ocr tesseract-ocr-eng gdal-bin libgdal-dev
```

### Clean-Checkout Setup

From a clean checkout, install all Python and web dependencies with:

```bash
make setup
```

### Running the Pipeline & Provenance Gate

```bash
cd pipeline
uv run bylaws --help
uv run bylaws check-provenance
uv run bylaws run-all --jurisdiction xx-test-fixture
uv run bylaws parse --jurisdiction xx-test-fixture --parser docling
uv run pytest -v
```

### Running the Web Application

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm run dev
```

## How Provenance Works

Every source document and map in any non-test jurisdiction is governed by the **Provenance Gate** (Rules R15–R17; see [`docs/provenance.md`](docs/provenance.md)):

1. **Remote `http(s)` Origin**: Every non-test source must have an `http(s)` `source_url` from an official publisher or mirror. Local `file://` or relative paths fail CI.
2. **Retrieval Record**: `bylaws acquire` records `fetched_at`, `requested_url`, `final_url` (after redirects), `http_status`, `content_type`, `content_length`, `response_headers` (`ETag`, `Last-Modified`, `Server`, `Date`), `sha256`, `fetched_by`, and a Wayback Machine snapshot URL (`archive_url` or `archive_failure_reason`).
3. **Generator Denylist**: `bylaws check-provenance` inspects PDF `Creator` and `Producer` metadata and fails CI if any PDF in a non-test jurisdiction matches a repository generator tool (`fpdf`, `pypdf`, `reportlab`, `StructuredBuildingBylaws`).
4. **Scheduled Source Verification**: `bylaws verify-sources --jurisdiction <id>` refetches each source and compares its SHA-256 against the recorded digest in a weekly GitHub Actions workflow (`.github/workflows/verify-sources.yml`).

## Contributing Corrections

Generated files in `data/processed/` are never hand-edited. All manual text, table, or map corrections are committed as reproducible YAML overrides under `data/overrides/<jurisdiction>/` with a cited page and reason. See [`CONTRIBUTING.md`](CONTRIBUTING.md).
